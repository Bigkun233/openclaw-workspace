## 需求先想清楚

我要的博客，核心就三点：

- 写文章要**快**（Markdown 直写，不碰后台）
- 部署要**简单**（最好 git push 就上线）
- 长期维护成本要**低**

## 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| WordPress | 生态全 | 要服务器、要维护 | ❌ |
| Hexo/Jekyll | 纯静态 | 主题定制麻烦 | 🔶 |
| Next.js | 功能强 | 偏重、学习成本高 | 🔶 |
| **Vite + React + Markdown** | 轻、可控、定制自由 | 需自己搭 | ✅ |

## 为什么是这套

### 1. 构建快

Vite 的冷启动和热更新都很快，改样式几乎即时看到效果。

### 2. 内容是纯文件

文章就是 `src/content/posts/*.md`，用 front-matter 描述元信息：

```yaml
---
title: 文章标题
date: 2026-09-12
tags: [前端, 建站]
---
```

新增文章**不用改任何代码**，构建时自动收录。

### 3. 上线灵活

纯静态产物，可以扔到任意静态托管：GitHub Pages、Vercel、CloudBase 静态托管都行。

## 踩过的坑

- **front-matter 解析**：不想引入重依赖，手写了个极简解析器，够用
- **路由刷新 404**：静态托管要配 SPA fallback（把 404 指向 index.html）
- **代码高亮样式**：highlight.js 的主题要手动 import

## 写在最后

工具是手段，**持续写**才是目的。选一套自己拿得住的，然后开始写。
